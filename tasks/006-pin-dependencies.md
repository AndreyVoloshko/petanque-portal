# Task 006: Pin Dependencies

## Goal

Make builds deterministic so that the same code always produces the same environment.

## Scope

1. Pin all Python dependencies to exact versions that work with Django 5.1.6 and Python 3.11.
2. Remove `boto` (legacy, replaced by `boto3`).
3. Use `pip-compile` from `pip-tools` for maintainable pinning.
4. Document supported Python version.
5. Run `pip-audit` for known vulnerabilities.

### Proposed Workflow

```
requirements.in    → human-maintained, loose constraints
requirements.txt   → generated by pip-compile, fully pinned with hashes
```

### Current Dependencies To Pin

- Django==5.1.6 (already pinned)
- boto3
- Pillow
- psycopg2-binary (switch from psycopg2 for simpler builds)
- django-countries
- django-extensions
- django-crispy-forms
- crispy-bootstrap5
- django-silk
- django-simple-captcha
- django-dbbackup
- django-storages[boto3]
- django-cors-headers
- transliterate
- gunicorn (currently installed only in Dockerfile, should be in requirements)

### Remove

- `boto` — legacy package, `boto3` covers all S3 needs

## Acceptance Criteria

- Fresh `pip install -r requirements.txt` installs identical versions every time
- `pip-audit` reports no critical vulnerabilities (or documents accepted risks)
- App boots and smoke tests pass after pinning
- `requirements.in` documents the intent; `requirements.txt` has pins
- README or docs document how to update dependencies

## Complexity

S

## Risk

Medium — a wrong pin can break the build. Mitigated by running smoke tests after.

## Big Win

High — prevents surprise breakage from upstream releases.
